## Urgent — la branche de transport reste exposée sur le dépôt public

Comme documenté hier (`content/inbox/runs/2026-08-14.md`), `recolte.yml` publie
sa récolte à la fois en artefact d'Action et sur une branche jetable
`veille/recolte`, forcée à chaque run (« BRANCHE JETABLE, NE PAS FUSIONNER »).
Cette session n'a **aucun accès réseau** au CDN Azure Blob qui sert l'artefact
(`productionresultssa12.blob.core.windows.net`, CONNECT refusé — 403 confirmé
à la fois via le SDK GitHub MCP et via un essai direct `curl` sur
`api.github.com/.../artifacts/.../zip`, qui redirige vers le même hôte bloqué :
refus de politique réseau, pas un problème d'authentification). La récolte de
ce run a donc été récupérée via `git archive origin/veille/recolte`, ce qui a
fonctionné mais reproduit exactement le problème signalé hier :

- `veille/recolte` contient à nouveau le texte intégral de huit pages tierces
  (`pages/gtaboom.com__*.txt`, ~340-630 lignes chacune) sur un dépôt **public**,
  au-delà de ce que couvre la matérialisation en fait reformulé.
- Aucun outil `mcp__github__*` disponible à cette session ne supprime une
  branche/ref (toujours vrai aujourd'hui : `create_branch` existe, son inverse
  non — vérifié dans le jeu d'outils avant d'écrire cette note).
- Contrairement à hier, ce run a pu aller jusqu'au bout (extraction, rédaction,
  tests) parce que la récolte était accessible par cette voie détournée. Mais
  chaque run laissera `veille/recolte` exposée tant que rien ne la nettoie, et
  la branche est recréée avant que qui que ce soit ait pu la supprimer.

**Action humaine nécessaire, deux jours de suite maintenant** :

```sh
git push origin --delete veille/recolte
```

Et un choix d'architecture à trancher : soit ajouter une action de suppression
de branche au serveur MCP GitHub exposé à ces sessions, soit faire de
`git archive origin/veille/recolte` (ce que ce run a fait) la voie officielle de
récupération de la récolte — auquel cas le contenu de tiers sur une branche
publique cesse d'être un accident et devient une décision produit à assumer
explicitement, avec ses implications IP.
