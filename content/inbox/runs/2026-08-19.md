## Écart d'environnement : pas de `gh` dans cette session

Cette session n'a pas le binaire `gh` (ni son authentification), contrairement
à ce que suppose l'enveloppe d'exécution du contrat (§1, « `gh`
authentifié »). Elle a en revanche les outils MCP GitHub et `git` avec des
identifiants de push déjà configurés (variables d'environnement injectées).
Substitutions faites, étape par étape :

- Étape 2 (déclenchement + lecture) : `mcp__github__actions_run_trigger`
  (`run_workflow`) au lieu de `gh workflow run`, `mcp__github__actions_list`
  au lieu de `gh run list`, `mcp__github__get_file_contents` au lieu de
  `gh api .../contents/...`. Fonctionne à l'identique.
- Étape 4 (suppression du transport) : `git push origin --delete` tenté au
  lieu de `gh api -X DELETE` — refusé en 403, voir plus haut. Aucun filet
  d'outil disponible.
- Étape 8 (PR) : `git push` (fonctionne, mêmes identifiants) puis
  `mcp__github__create_pull_request` au lieu de `gh pr create`.

Rien de tout cela n'a nécessité de contourner une règle du contrat ; ce sont
des équivalents fonctionnels, sauf pour la suppression de ref où aucun
équivalent n'existe dans cette enveloppe.
