## Le transport a changé sous mes pieds, dans le bon sens

Le prompt stocké de cette Routine décrit encore `gh run download` — l'ancien
chemin par artefact. Il est obsolète : `recolte.yml` documente maintenant en
en-tête que la récolte voyage par la branche jetable `veille/recolte`, lue via
l'API `contents` de `api.github.com`, précisément parce que le téléchargement
d'artefact redirige vers un CDN Azure (`productionresultssa6.blob.core.windows.net`)
que la passerelle de sortie de cette session refuse au CONNECT. `gh` lui-même
n'est toujours pas installé dans cet environnement ; le chemin documenté par
`.claude/agents/data-scout.md` (lecture de `veille/recolte` via
`mcp__github__get_file_contents`) fonctionne sans accroc. **Suggestion pour
un humain** : mettre à jour le prompt de cette Routine pour refléter
`veille/recolte` plutôt que `gh run download`, afin que le prochain run n'ait
pas à redécouvrir le contournement.

**`veille/recolte` non supprimée intégralement — blocage d'environnement
récurrent.** Aucun outil MCP disponible ne supprime une ref/branche
(seulement `create_branch` et `delete_file`), et l'écriture Git directe sur
ce dépôt (`git push origin --delete`) échoue en 403. Le fichier
`recolte.json` a pu être supprimé via `delete_file` (commit dédié sur cette
branche), donc le contenu tiers ne séjourne plus dans le repo — mais la ref
elle-même reste techniquement présente jusqu'à son prochain écrasement par
`Récolte`. À supprimer par un humain ou par une étape disposant des droits
